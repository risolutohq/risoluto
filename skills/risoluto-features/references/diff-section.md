# `## Changed since last spine` section template

Goes at the top of `RISOLUTO_FEATURES.md`, immediately under the frontmatter list and the first `---`. Generated by `scripts/diff_spines.py` from the JSON sidecar — you should never write this by hand.

## Shape

```markdown
## Changed since last spine

From `cbf423b` → `e4f5g6h` — **3 added · 5 modified · 1 removed**.

### Added

- [Feature name with a link](#feature-name-with-a-link) — _Bundle_ (#issue, #issue)
- ...

### Modified

- [Existing feature](#existing-feature) — _Bundle_ — fields: `observable_behaviors, citations`
- ...

### Removed

- **Old feature** (`old-feature-id`) — _Bundle_

---
```

## Rules

- **Always** present, even if nothing changed. When empty, the body reads `_No feature-level changes detected since the previous spine._` This single line tells the reader "yes, the skill did run; no, it found nothing worth reporting." Silence reads as oversight.
- **One subsection per category** (Added / Modified / Removed). Omit a subsection if its list is empty — don't print empty headings.
- **Anchors are GitHub-style slugs** of the feature name: lowercase, alphanumerics + hyphens. GitHub's renderer produces the same slug for an H3, so the link resolves.
- **Bundle name** appears italicised after an em-dash. Don't repeat the bundle in the entry link text.
- **Issue numbers** appear as `(#N, #M)` only in the Added subsection. Modified and Removed entries skip them — the reader can click through if they want.
- **Modified subsection lists which fields changed**, in alphabetical order, comma-separated in a code span. The reader scans this to decide whether the change matters to them.
- **Removed subsection links the feature name** to its tombstone — the body is retained in-bundle with a `⚠️ Removed` marker (see `feature-entry-template.md`), so the anchor resolves — and shows the `id` in code so a downstream consumer can grep for it.

## Cold start

On the very first run (no previous JSON to diff against), the section reads:

```markdown
## Changed since last spine

_Initial spine cut at `<sha>` — **118 features** recorded for the first time._

---
```

No subsections. The reader knows there's nothing to diff.

## Don't

- ❌ Don't summarise reasons in this section. The reader wants the _scoreboard_ first; if they want the _why_, they jump to the entry.
- ❌ Don't include cosmetic changes (line-range shifts where the symbol and behavior are identical). The diff section is for material changes only.
- ❌ Don't reorder the subsections. Added → Modified → Removed, always. Readers scan in that order.
- ❌ Don't make this section longer than ~30 lines on a typical run. If it is, you probably included cosmetic noise.
